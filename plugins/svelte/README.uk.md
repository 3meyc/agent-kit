# svelte

[English](README.md) · **Українська**

Конвенції для проєктів на Svelte 5: руни, доступність, Vitest і стилі на Tailwind. Кожна з них —
скіл із `paths:`, тож Claude Code завантажує його, коли сесія торкається відповідного файлу.
Нічого специфічного для проєкту тут немає: власна дизайн-мова, компоненти й теки проєкту
лишаються в проєкті. Потребує `core`.

## Встановлення

Коли маркетплейс `agent-kit` уже додано (див. [кореневий README](../../README.uk.md)):

```bash
claude plugin install svelte@agent-kit
```

## Скіли

| ID | Скіл | Завантажується для | Що охоплює |
| --- | --- | --- | --- |
| 1 | `svelte:runes` | `**/*.svelte`, `**/*.svelte.ts`, `**/*.svelte.js` | Лише руни, одна роль на руну, пропси лише для читання, де тримати стан, декларативні шаблони, розмір компонента, реактивність, автофіксер Svelte MCP |
| 2 | `svelte:a11y` | `**/*.svelte` | Семантичний HTML, клавіатура, фокус, `id` і підписи полів форм, приховані панелі, кнопки лише з іконкою, діалоги, вкладки, статуси й live-регіони, причини вимкнення |
| 3 | `svelte:vitest` | `**/*.test.ts`, `**/*.spec.ts`, `**/*.test.js`, `**/*.spec.js`, `**/vite.config.ts`, `**/vitest.config.ts` | Vitest для нових тестів, без API тест-раннера Node, міграція під час правки, запуск через скрипт проєкту, тести компонентів через те, що бачить користувач |
| 4 | `svelte:tailwind-styling` | `**/*.svelte`, `**/*.css`, `**/tailwind.config.*` | Спершу утиліти, без інлайн-стилів, винесення повторів, токени теми замість довільних значень, темний режим через клас, читабельні списки класів |

Опис скіла показується в кожній сесії, а тіло завантажується лише тоді, коли модель його викликає
(див. [спайки](../../docs/spikes.uk.md), S2 і побічна знахідка 2). Скіли заповнюють те, що проєкт
лишив відкритим: власні правила проєкту й навколишній код мають перевагу, коли вони розходяться.

## Що лишається в проєкті

1. Структура тек для хелперів, сервісів і сторів, а також пороги складності чи дублювання.
2. Дизайн-токени, розміри контролів, радіус кутів, скролбари й назви спільних компонентів.
3. Бібліотека іконок, локалізація й правила перекладених підписів.
4. Посилання на власні компоненти діалогів, вкладок, полів і завантаження та на рецепти проєкту.

## Як прибрати копії з проєкту

Проєкти, що тримали ці конвенції у файлах `.claude/rules/*.md`, можуть їх прибрати: `kit doctor`
і `/core:kit-adopt` показують копії, названі в [kit-owned.json](kit-owned.json). Більшість цих
файлів містить і рядки, специфічні для проєкту; перенесіть їх у правило з іншою назвою, перш ніж
видаляти копію.
