# core

[English](README.md) · **Українська**

Базовий плагін, від якого залежать усі інші плагіни agent-kit: постійні правила для чату й
оболонки, агенти перевірок і пошуку, хуки редагування й оболонки, а також команди, що переводять
проєкт на набір і тримають його в порядку. Усе береться з `kit.json` проєкту; нічого специфічного
для проєкту тут немає.

## Постійні правила

Хук `SessionStart` друкує [rules/always-on.md](rules/always-on.md), а Claude Code додає цей текст у
контекст сесії (без копії в проєкті). Там:

1. **Вивід у чат**: довжина, форматування, блоки команд із кнопкою запуску, звіт про неперевірене.
2. **Оболонка за ОС**: спершу визначити оболонку, пастки PowerShell, переносні команди набору
   `count-lines` і `git-branch-context`.
3. **Обмеження інструментів**: що робити, коли інструмент відмовляє, і загальні обмеження
   (синхронізація з базовою гілкою в застосунку, класифікатор авторежиму, хуки набору, машинні
   інструменти, CI). Власні обмеження проєкт тримає в окремому правилі.

## Хуки

Плагін не можна вимикати по одному хуку, тому кожен хук читає `hooks.off` з `kit.json` і тихо
завершується, якщо його id там є.

| ID | Id хука | Подія | Що робить | Нічого не робить, коли |
| --- | --- | --- | --- | --- |
| 1 | `rules` | SessionStart | Друкує постійні правила | його id є в `hooks.off` |
| 2 | `update-check` | SessionStart | Коротке повідомлення, коли коміт встановленого плагіна набору відрізняється від ref його маркетплейсу, з двома командами оновлення; SHA з віддаленого репозиторію кешуються на шість годин | нічого не відстає, віддалений репозиторій недоступний або сесія перезапустилася після стиснення |
| 3 | `lint-edited-file` | PostToolUse Edit, Write, MultiEdit | Запускає `lintOnEdit.command` для зміненого файлу; помилку бачить агент (exit 2), правка не скасовується | немає `lintOnEdit` або файл не відповідає жодному шаблону з `lintOnEdit.match` |
| 4 | `shell-deletions` | PreToolUse і PostToolUse Bash, PowerShell | Знімає знімки відстежуваних файлів, які видаляє команда зі скриптом, для журналу сесії | `ledger` не `true` або команда не запускає скрипт |
| 5 | `codegraph-sync` | PreToolUse Bash, PowerShell, MCP-інструменти CodeGraph | Синхронізує власний індекс CodeGraph пов'язаного робочого дерева перед запитом | у робочому дереві немає `.codegraph/codegraph.db` або немає CLI `codegraph` |

Хуки 4 і 5 ділять один процес PreToolUse для команд оболонки (`hooks/shell-pre.mjs`), тож команда
запускає один `node`, а не два. Жоден хук не блокує виклик інструмента; збій — це один рядок у stderr.

## Команди

| ID | Команда | Що робить |
| --- | --- | --- |
| 1 | `/core:check [<command> \| all]` | Запускає `commands.*` з `kit.json` в агенті Haiku `check-runner`, який звітує лише про збої. Без аргументу: `check`, `lint`, `test` |
| 2 | `/core:dev` | Запускає dev-сервер на `devServer.port` через відповідний запис у `.claude/launch.json`, у панелі Browser застосунку |
| 3 | `/core:kit-doctor` | Перевіряє `kit.json` за схемою, потрібні плагіни, оголошення обох маркетплейсів, копії файлів набору, встановлені версії |
| 4 | `/core:kit-adopt` | Складає чернетку `kit.json`, оголошує маркетплейси й плагіни в `.claude/settings.json`, перелічує локальні файли, які тепер дає набір; спершу пробний запуск, нічого не видаляє |
| 5 | `/core:kit-inventory [--out <dir>]` | Інвентаризує інструменти агентів у ваших локальних репозиторіях і міряє розбіжність між копіями |
| 6 | Скіл `codegraph` | Як користуватися CLI CodeGraph (impact перед зміною спільного символу; члени, прочитані як `obj.prop`, шукати grep). Діє лише там, де є `.codegraph/` |

За документацією, короткі назви (`/check`, `/dev`, …) теж працюють, поки їх не має інша команда
_(тут не перевірено)_. Агенти: `check-runner` (запускає перевірки, звітує лише про збої) і
`repo-sweep` (пошук лише для читання по багатьох файлах, що повертає висновок).

## Команди оболонки

Доступні в PATH інструмента Bash, поки плагін увімкнений:

| ID | Команда | Що робить |
| --- | --- | --- |
| 1 | `count-lines <file>...` | Кількість рядків, однаково на кожній ОС |
| 2 | `git-branch-context` | Гілка, upstream, базова гілка за замовчуванням і `baseBranch` з `kit.json` у JSON |
| 3 | `kit doctor \| adopt \| inventory \| drift \| update-check \| commands \| dev` | Команди, на яких стоять скіли вище |
| 4 | `kit-docs-parity [path...]` | Перевіряє, що в кожній парі `name.md` / `name.uk.md` збігаються заголовки, таблиці, блоки Mermaid, блоки команд і нумеровані пункти |

Скіли викликають `node "${CLAUDE_PLUGIN_ROOT}/src/kit-cli.mjs" …`, якому PATH не потрібен.

## Поля kit.json, які читає плагін

| ID | Поле | Хто читає |
| --- | --- | --- |
| 1 | `commands.check`, `lint`, `test`, `build` | `/core:check` (ніколи `commit`, `land` чи `commitAudit`) |
| 2 | `devServer.port` | `/core:dev` |
| 3 | `hooks.off` | кожен хук (id вище) |
| 4 | `ledger` | `shell-deletions` (працює лише при `true`); `kit doctor` (тоді чекає `session`) |
| 5 | `baseBranch` | `git-branch-context` |
| 6 | `lintOnEdit` _(запропоноване, немає у схемі v1)_ | `lint-edited-file` |
| 7 | увесь файл | `kit doctor` перевіряє його за схемою з `schema/` |

`lintOnEdit` приймає команду й необов'язкові шаблони; `{file}` замінюється на шлях відносно
репозиторію в лапках, інакше шлях дописується в кінець. Шаблон без `/` збігається з назвою файлу
будь-де.

```json
{ "lintOnEdit": { "command": "pnpm exec eslint --no-warn-ignored {file}", "match": ["*.ts", "*.svelte"] } }
```

## Список репозиторіїв для інвентаризації

`/core:kit-inventory` бере репозиторії з вашої власної конфігурації, ніколи з набору:
`~/.config/agent-kit/inventory.json` (або в `$XDG_CONFIG_HOME`). `reference` — копія, від якої
міряють розбіжність; `extraRoots` і `extraFiles` додають теки й файли до перегляду.

```json
{ "repos": { "app": "~/code/my-app", "api": "~/code/my-api" }, "reference": "app", "extraFiles": ["lefthook.yml"] }
```

## Прибирання копій у проєкті

Проєкт, що мав власні копії цих файлів, зберігає їх, поки хтось їх не прибере: `kit doctor` і
`/core:kit-adopt` перелічують кожну. Файли набору названо в [kit-owned.json](kit-owned.json), а
також кожен агент і скіл плагіна. Інший плагін або надбудова може мати власний `kit-owned.json`.
