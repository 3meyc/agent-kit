# Перевірки поведінки плагінів

[English](spikes.md) · **Українська**

Дизайн у [architecture.uk.md](architecture.uk.md) і [changing.uk.md](changing.uk.md) спирається на
поведінку плагінів Claude Code. Ця сторінка фіксує, що показали реальні запуски, щоб подальша
робота трималася фактів, а не лише документації.

## Метод

| ID | Пункт | Значення |
| --- | --- | --- |
| 1 | Claude Code | CLI 2.1.300, macOS |
| 2 | Плагіни | Тимчасові плагіни й маркетплейси, ніколи не зливаються |
| 3 | Пісочниця | Окремий git-репозиторій поза всіма проєктами; встановлення з `--scope local`; після перевірок видалений |
| 4 | Запуски | Безінтерактивний `claude -p`. Де відповідь моделі не потрібна, транскрипт сесії (`~/.claude/projects/<dir>/<id>.jsonl`) точно показує, що потрапило в контекст |
| 5 | Віддалені посилання | Тимчасові теги `spike-w03-*` у цьому репозиторії, після перевірок видалені |
| 6 | Модель | Sonnet (`--model sonnet`) для запусків, яким потрібна відповідь моделі (перевірка S1a, S2, S4b); Haiku для решти. Плагіни й хуки рівня користувача на тестовій машині лишалися ввімкненими |

Редагування `src/App.svelte`: правило 5/5, скіл 5/5. Створення `src/Counter.svelte`: правило 5/5, скіл 5/5. Запит без слова Svelte ("The home page greeting should say Hello Kit…"): правило 5/5, скіл 5/5; інструмент Skill викликано в кожному запуску зі скілом (`"name":"Skill"`, `spk-core:spk-svelte`). Дві попередні серії з цим запитом зламали запити на схвалення команд оболонки; у кожному їхньому запуску, де файл таки змінено, домовленості дотримано (правило 6/6, скіл 5/5) | Використовувати в плагінах скіли з `paths:`. На відміну від правила, тіло скіла завантажується лише тоді, коли модель його викликає, а опис є в переліку кожної сесії (побічна знахідка 2), тож опис має бути коротким і конкретним. 5 запусків на клітинку з однією моделлю — мала вибірка: перевірити на робочій моделі, якщо домовленість почне губитися |

| S8 | Після переміщення зафіксованого тега чи підхоплює наступна сесія новий коміт при ввімкненому автооновленні? | ні | Тег `spike-w03-move` переміщено з v1 на v3, `"autoUpdate": true` у записі маркетплейсу. | S10 | Скільки виводу хука `SessionStart` доходить до сесії? | 10 000 символів на хук | Пілотний проєкт завантажив плагін надбудови, чий хук SessionStart друкував 10,7 КБ правил (`claude -p`, CLI на macOS): у транскрипті є `<persisted-output> Output too large (10.7KB)…` з попереднім переглядом на 2 381 символ і шляхом до збереженого файлу, тож більшість правил до моделі не дійшла; 4,3 КБ `core` у тій самій сесії дійшли повністю. ## Побічні знахідки

| ID | Знахідка | Доказ |
| --- | --- | --- |
| 1 | Видалення маркетплейсу в одному проєкті видаляє його плагіни в усіх проєктах на машині | `claude plugin marketplace remove spike-gh` у проєкті 2, потім `claude plugin uninstall spk-gh@spike-gh` у проєкті 1 → `Plugin "spk-gh@spike-gh" not found in installed plugins` |
| 2 | Скіл плагіна з `paths:` є в переліку скілів кожної сесії, ще до того, як зачеплено відповідний файл; його тіло завантажується лише тоді, коли модель його викликає | Транскрипт простого `claude -p x` містить `spk-core:spk-svelte` у `skill_listing` |
| 3 | Застосунок для робочого столу запускає Claude Code з `DISABLE_AUTOUPDATER=1`, що вимикає автооновлення плагінів | Журнал налагодження: `Plugin autoupdate: skipped (auto-updater disabled)` |
| 4 | Скіл плагіна, що читає власні файли плагіна (`references/`, `assets/`) інструментом Read, читає поза проєктом: кожне читання просить дозволу, а запуск без інтерфейсу його відхиляє. Бачили з `--plugin-dir`; встановлену копію в кеші плагінів не перевіряли, але вона теж поза проєктом. Вихід: помічник у `bin/` друкує вбудований документ (`sdlc-kit show <doc>` плагіна `sdlc`) | Лінія `sdlc` хвилі 1, `claude -p` без інтерфейсу з `--plugin-dir` (PR #3) |
| 5 | `allowed-tools: Bash(<bin>:*)` у frontmatter скілу плагіна заздалегідь дозволяє голу команду з `bin/` цього плагіна: вона запускалась без інтерфейсу й без запиту дозволу. Команда `/session:git` з `context: fork` все одно змусила відгалуженого агента питати дозволу на `git status`, тож `allowed-tools` команди може не доходити до відгалуженого агента | Лінія `sdlc`: `sdlc-kit` запускався з `/sdlc-intent` і `/sdlc-plan` без запиту (PR #3); лінія `session`, запуск без інтерфейсу (PR #5) |
